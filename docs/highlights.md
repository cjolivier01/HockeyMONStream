# Highlights from recorded games

Open **Highlights…** in the main window's top bar after selecting a saved game in Program mode. Add named intervals in the order they should appear in the video. An event time and duration put 75% of the interval before the event and 25% after it; an explicit start and end keep the entered bounds. Times use `HH:MM:SS[.mmm]`, including recordings longer than 24 hours. Event intervals beginning before zero are shortened to start at zero. The list and export base name are saved in the game's `highlights.json` without editing calibration configuration.

**Preview selected**, **Preview all**, **Loop selected**, and **Loop all** run the ordinary source pipeline with a local render output, regardless of the main window's archive checkboxes. Each interval starts a new runner, so there is a startup pause between intervals and at a loop boundary. **Stop** cancels the queued preview or export.

Export selects Program, 4K Program, and Stitched independently. The dialog launches a fresh `hstream-cli` source run for each interval, with `--start-time`, `--clip-end-time`, a timed-run watchdog, and explicit sink output paths. Runtime seek is render-only and is not used for encoded clips. Each run uses the existing synchronized camera playlist, calibration, Program processing, GPU encoder, and source-linked audio. A clip-end result distinguishes the requested boundary from natural source EOS; if an interval reaches natural EOS, the available part is kept. A start beyond EOS fails.

The runner writes separate MKV work files under a private `.highlights-work-*` directory in the configured working output root. The dialog checks that clips for each output have matching video and audio streams and verifies the video packet end, then uses FFmpeg's concat demuxer and stream copy to make one fast-start MP4 per selected output. A private game-local finalization directory keeps publication on the destination filesystem. The concat manifest trims encoded packets at the video end or requested interval end, whichever comes first. Boundaries are limited by video frames, audio packets, and codec reordering; this is not sample-exact editing. Overlapping intervals remain separate and appear in list order. Failed or cancelled exports retain their MKV work files for inspection.

Completed filenames follow `<game-id>-<base-name>-<route>-<number>.mp4`, where `route` is `program`, `program_4k`, or `stitched`. Publication never overwrites an existing file. The dialog freezes the selected interval list and output choices when a job starts. Close it before starting a normal pipeline run; two source graphs are not run concurrently from the main window.

The interval model and atomic JSON save are in `src/apps/hstream-ui/HighlightPlan.*`; process, probe, concat, and publication ownership are in `HighlightsDialog.*`. `PipelineApp.cpp` owns the completed-output clip-end marker and stop request. The source video remains GPU-resident through the existing encode and preview graphs; FFmpeg handles compressed packets during the join.

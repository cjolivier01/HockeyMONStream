# Highlight reels

Open **Highlights…** after selecting a saved game. Select a published Program, 4K Program, or Stitched archive. Highlights reads that archive; it does not restitch cameras or rerun detection. The archive sidecar supplies its game-time origin. **Archive starts at** corrects older archives and remembers the correction beside the file.

Add event times and durations, or exact source ranges. Times accept seconds, `MM:SS`, or `HH:MM:SS`, with optional `.mmm`. Event clips include 75% of the entered duration before the event and 25% after it. The table is the reel sequence: move, duplicate, or remove rows. **Add card** inserts an ordinary row after the selection, so titles and intermissions can appear anywhere, and adjacent clips can have direct cuts.

## Cues and detail annotations

Select a video row and open **Annotations / card**. The control column opens at the width its fields need, capped by half the screen and the space needed for the preview. On smaller screens, scroll to reach fields that cannot fit; moving the dialog to another screen adjusts its minimum width. Inspect a chosen clip time to hold an authored GPU frame. Click the image to position a fixed cue, then refresh the frame to inspect the result. Add each cue yourself; nothing repeats or inserts a later marker automatically. The default is a yellow blinking arrow lasting up to two seconds.

Each cue has independent clip-relative start/end controls, type (`arrow`, `text`, `box`), color, size, stroke thickness, text weight, and blink phase. Coordinates and dimensions are fractions of the output image. An arrow's X/Y is its tail; its end offsets specify direction and length. Boxes use the same offsets as dimensions. Text begins at X/Y. Several cues can overlap. **Apply cue** saves the current controls; changing the selected cue and saving the dialog also apply them.

Movement can be fixed, manual keyframes, or a recorded track. Manual positions use one `clip time, X, Y` row per keyframe, in increasing time order. Clicking at different inspected times adds or replaces a keyframe. Trimmed cues can retain negative clip-relative times or positions beyond the out point; these remain editable without shifting the source event. Positions interpolate linearly; the first/last position holds to the cue's boundary. These keyframes let an author follow a hand or contact point without claiming that a person's bounding box tracks their hand.

For a tracked cue, load the telemetry SQLite database's runs and select the run that produced the archive. The database field defaults to `<game-id>_telemetry-N.db` in the game directory, with `N` taken from the selected archive's suffix; an existing older database name for that same generation is also accepted. An unnumbered archive uses legacy generation zero and leaves the field empty if no matching database exists. **Choose database** handles custom archive names or databases stored elsewhere. Set **Telemetry PTS minus game time** if the two timelines have different origins. **Find tracks** lists IDs and their source/geometry/seek/reset context at the cue's start. Select a player or referee by ID or click its box at that time, verify the run/archive binding, and **Attach selected track**. The default arrow ends at the person's upper bounding-box center. X/Y become adjustable offsets from that anchor.

The archive geometry selector must match the recorded media: `program` uses the saved Program camera crop and edge rotation, `stitched` uses the uncropped proportional canvas, and `program-full` handles a rotated no-crop Program archive. These are explicit author bindings because older archive sidecars do not identify a telemetry run. Missing camera/rotation evidence prevents Program tracking. Referees are selectable only if they were tracked in that run. **Find tracks** queries at the cue start; inspect that same clip time before clicking a player, or select its recorded ID directly. Changing the inspection time requires a refresh before any positioning click.

A track capture saves up to 4,000 observations over at most two minutes, scoped to one run, source, geometry, seek epoch and reset epoch. Gaps over 100 ms hide the cue; another ID is never substituted. Correct an identity switch with manual keyframes or another explicitly selected cue. The retained observations make preview and export independent of later database changes. A different archive, changed file size/modification time, or edited archive origin requires selecting the track again.

For example, create an arrow at 0–2 seconds and explicitly create another at 8–10 seconds. Add fixed heavy yellow “Holding penalty” text with a separate manual arrow at the contact point. Place fixed or tracked blinking “WHISTLE!” at the time you heard the whistle, before the late hit. The editor does not detect these events.

## Cards

Cards have editable text, background/text colors, type size/weight, and duration. Enable **Matchup** for two team names, optional heading and logos, and a required valid `YYYY-MM-DD` game date. A date already present in the game identifier prefills the field; an unknown date stays empty. The current/export date is never substituted. Generic section cards need no date.

**Choose A/B logo** imports a bounded raster image into the game's `highlight-assets/` directory as a content-addressed PNG. Original files can then be moved or deleted without breaking the reel. Saving a valid matchup card imports a path typed or pasted into the field the same way and rewrites the field to the stored copy; opening or previewing a card never writes to the game. A path that names nothing, or names something that cannot be decoded, is saved as entered and reported by preview and export rather than blocking the rest of the card. If a readable logo cannot be retained because storage fails, Save displays the error and leaves the dialog open for correction and retry. Already-retained logos are reused without rewriting the image, and absolute paths to them become relative so the game directory can move. Logos fit proportionally next to the team names. The card layout fits uniformly into the archive aspect ratio, with the chosen background filling any margins, so panorama exports keep logos and text proportional. Missing retained assets fail preview/export with an explanation. Cards have silent stereo audio and can be previewed or exported alone without an archive.

## Playback and export

**Preview selected/all** and **Loop selected/all** show the authored sequence on the native NVIDIA/X11 preview. Resize or maximize the dialog; the preview's top-right icon expands/restores its layout. **Stop** restores that layout and cancels the active job. Cancellation finishes asynchronous cleanup before another job starts or the dialog closes.

Preview and export share `HighlightReelPipeline`, `HighlightScene`, and the CUDA texture compositor. One archive decoder runs at a time. Decoded NVMM frames are copied device-to-device into six owned output surfaces, then annotated there. Video pixels are never downloaded for drawing. Only static text/shapes/cards/logos are rasterized on the CPU and uploaded once per item; the artwork budget is 128 MiB per item. Preview scales to at most 1280×720; export retains even archive dimensions up to 8192 per side. Eight-bit exports use H.264 or HEVC according to the archive; ten-bit exports use RGB10A2 rendering and HEVC/P010 encoding. NVIDIA decoding, conversion and hardware encoding are required. The desktop feature remains excluded from the repository's Jetson build, as the existing Qt UI is; the shared CUDA compositor builds separately.

Video and stereo 48 kHz PCM audio are placed on one output timeline. Audio is trimmed at sample boundaries, with silence for cards, missing audio and gaps. Decoded timestamps map through their source segments so MP4 edit lists retain delayed audio/video positions. The controller seeks to a keyframe, restarts the NVIDIA decoder after preroll, and trims decoded frames/samples itself without a decoder stop-time seek. Source frame timestamps determine video boundaries; cuts can fall between frames, with precision limited to the source frame cadence. The native pipeline drains one encoder and MP4 mux at reel end; AAC padding occurs once, rather than accumulating at every join. There are no FFmpeg rendering, encoding or concatenation jobs. The dialog still uses `ffprobe` solely for archive inspection.

AAC uses GStreamer's `avenc_aac` element from `gstreamer1.0-libav`, included in the desktop package dependencies. After mux EOS closes the file, `HighlightMp4Audio` updates the audio track's standard MP4 edit list to skip the 1024-sample priming interval and end at the authored reel duration. Encoded preroll remains intact for decoder overlap state, and the encoder drains its tail at EOS. This step reads bounded metadata headers and changes fixed fields without reading video payloads or moving media/chunk offsets. Unexpected metadata prevents publication.

Completed files use `<game-id>-<base-name>-<route>-<number>.mp4`. Publication happens only after mux EOS, file synchronization and a non-overwriting hard link. Success and cancellation remove the private game-local `.highlights-export-*` directory. Failed exports retain nonempty work output for diagnosis. A cards-only reel uses the `cards` route when no archive is selected.

`HighlightPlan` saves schema 2 in game-local `highlights.json` and reads legacy schema 1 interval-only plans. The selected archive is retained; a missing saved archive cannot silently select a different generation. Cue times are stored in absolute source/game time: changing earlier card durations or row order cannot move an event. Trimming clips also preserves those times; only the portion inside the new clip is rendered. Extend or recapture moving cues when new footage needs additional positions. Unsaved authoring changes are committed only when the item dialog is saved.
